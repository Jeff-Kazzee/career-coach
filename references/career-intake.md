# Career Intake and Baseline

## What this reference is for

Build a usable career baseline, diagnose the current bottleneck, and turn an unclear situation into a 30-day operating plan. This is not a personality test or a life-story interview.

## When the agent should read it

Read this for Baseline Mode, Career Change Mode, first-time coaching, long periods of stalled progress, or when previous advice lacks enough context.

## The concrete process

### 1. Start with available evidence

Before asking questions, inspect anything already provided: resume, profile, portfolio, GitHub, job descriptions, application history, work reviews, project list, learning log, or prior goals.

Maintain three buckets:

- **Known:** directly supported by the user's words or artifacts.
- **Unknown:** information that could materially change the plan.
- **Assumption:** a temporary working assumption stated plainly.

Do not ask the user to repeat information already available.

### 2. Collect the minimum useful intake

Use `assets/career-intake-template.md`. Ask in one compact batch when possible. Essential fields are:

- Current work and income situation
- Target role, direction, or outcome
- Current skills and recency
- Proof of skill: work, projects, samples, results, feedback
- Experience, including unpaid, informal, volunteer, caregiving-adjacent, or self-directed work when relevant
- Education, licenses, certifications, and genuine credential gates
- Existing resume, LinkedIn, GitHub, portfolio, or site
- Current search or advancement activity and results
- Income floor and desired range, clearly labeled as user requirements rather than market facts
- Location, remote, schedule, transportation, work-authorization, and accessibility needs
- Time, energy, money, equipment, internet, and privacy constraints
- Strengths, weak points, confidence, and the user's own bottleneck hypothesis

Ask about functional conditions—such as maximum sustainable hours, need for asynchronous work, or difficulty with commuting—not medical diagnoses.

### 3. Classify constraints

Sort each relevant constraint as:

- **Hard:** cannot be violated now.
- **Soft:** strongly preferred but negotiable for a meaningful benefit.
- **Unknown:** needs research, testing, or professional advice.

Do not plan around imaginary capacity. Convert time and energy into a weekly operating budget, such as three 45-minute sessions, rather than “work on this every day.”

### 4. Create target hypotheses

When the user has no clear target, propose no more than three:

1. **Primary target:** best current combination of fit, viability, and interest.
2. **Adjacent target:** uses more existing proof or has a shorter bridge.
3. **Fallback or cash-flow target:** protects income or stability without pretending it is the final destination.

For each target, research current facts when tools are available:

- Typical tasks and work context from O*NET
- Entry requirements, pay, and outlook from BLS for the relevant geography and period
- Current postings to test actual employer language and requirements
- Credential or licensing gates from authoritative sources

Never infer that a national projection guarantees local openings or an individual's outcome.

### 5. Build a proof inventory

For each claimed skill, record:

| Skill | Claimed level | Last used | Proof | Independent feedback | Target relevance | Missing proof |
|---|---:|---|---|---|---|---|

Accept credible proof from employment, projects, freelance work, open source, volunteering, school, communities, caregiving systems, or self-directed work. Label the context accurately; do not relabel informal work as employment.

### 6. Locate the bottleneck

Choose the main bottleneck category:

- Direction or target definition
- Market alignment or access
- Skill
- Proof or portfolio
- Positioning or materials
- Search execution
- Interview conversion
- Workplace performance or visibility
- Constraint or capacity mismatch
- Confidence or avoidance that is blocking action

Use funnel evidence. Examples:

- Many relevant applications and no screens points first to fit, materials, proof, or channel—not interview skill.
- Screens but no next rounds points first to recruiter-screen communication, logistics, or role match.
- Strong work with no advancement points first to expectations, impact, visibility, sponsorship, or organizational limits.

State alternate explanations when evidence is thin.

### 7. Score the current system

Use `assets/career-scorecard-template.md`. Score only dimensions with enough evidence. A zero means unknown or not started; it does not mean the user has no value.

The lowest score is not automatically the priority. Pick the factor most likely to unlock the user's stated outcome within current constraints.

### 8. Select three leverage points

Rank potential actions by:

- Expected effect on the bottleneck
- Time to feedback
- Credibility of the resulting evidence
- Cost and accessibility
- Reusability across opportunities
- Dependence on other people or luck

Choose one primary, one supporting, and one risk-control action.

### 9. Build the 30-day plan

Use `assets/30-day-plan-template.md`. It must contain:

- One outcome hypothesis
- One primary metric and two supporting metrics
- Four weekly milestones
- Minimum, standard, and stretch versions
- A stop or reassessment rule
- A portable evidence log

Prefer outputs such as a reviewed work sample, ten researched employers, four interview stories, or a manager-aligned expectations document over vague verbs such as “learn,” “network,” or “improve.”

### 10. End with one bounded action

The first action should fit one realistic work session. Define done visibly.

Example:

> Draft a one-page proof inventory for the last three projects. Done means each project has a problem, your actions, tools used, result, and one link or artifact.

## Baseline output format

```markdown
# Career snapshot

## Current position
[Known facts and constraints]

## Target hypothesis
[Primary, adjacent, and fallback only when useful]

## Bottleneck diagnosis
[Primary bottleneck, evidence, uncertainty, alternate explanation]

## Top three leverage points
1. [Primary]
2. [Supporting]
3. [Risk control]

## 30-day plan
[Weekly milestones, capacity versions, measurement, reassessment rule]

## First next action
[One work session; definition of done]
```
